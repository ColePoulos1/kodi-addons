Inspected November 19, 2026. The submodule pins Fen Light+ 2.5.4 at `89415039efee51fb0718278fac8a9aba3e5f0897`. The version was committed November 3 and an IPv4 fallback fix was merged November 4. The November 18 commit refreshed show data. [Source tree](https://github.com/thejason40/FenLightPlus/tree/89415039efee51fb0718278fac8a9aba3e5f0897) · [Release](https://github.com/thejason40/FenLightPlus/commit/ccebd44d522b39559aa2110f807035c15d7284c8) · [Networking fix](https://github.com/thejason40/FenLightPlus/commit/5f9f9913e02739605baa472c0e4a12b144287090)

Paths below start at `plugin.video.fenlight/resources/lib/` within that checkout unless indicated. These are integration points observed in the source. Live behavior on the target device still needs verification.

| Existing behavior | Where to look | Design consequence |
| --- | --- | --- |
| The native Kodi settings page opens a custom settings window. Defaults, persistence, display, and getters span several files. | `../settings.xml`, `windows/settings_manager.py`, `caches/settings_cache.py`, `modules/settings.py` | Add profile and language choices through the existing settings flow. Editing the XML launcher alone will never expose them. |
| Persistent filters include 3D, HDR, Dolby Vision, HEVC, AV1, AI-enhanced/upscaled files, and audio formats. Upstream defaults 3D to Include. | `modules/sources.py` (`filter_keys`, `special_filter`, `filter_audio`), `modules/source_utils.py`, `caches/settings_cache.py` | Default the fork's existing 3D setting to Exclude on fresh installs. Honor explicit saved exclusions and the existing Dolby Vision/HDR fallback handling. Audio format and spoken language are separate features. |
| Source sorting offers all six permutations of quality, provider, and size, with a size direction. There are ordered autoplay preferences, folder/cloud pins, and separate movie/episode size limits or a runtime-based line-speed ceiling. | `modules/settings.py` (`results_sort_order`, `preferred_autoplay`), `modules/sources.py` (`process_results`, `filter_results`, `sort_preferred_autoplay`, `sort_first`) | Keep the manual list in existing order. Apply explicit bounds first. In smart autoplay, honor pins, use saved format preferences once, and use existing order to break ties. Named reusable sets of stream filters were not established by this inspection. |
| Normal processing splits uncached results, sorts, filters, and reapplies preferences. Folder exemptions, “ignore filters” recovery, pack-cache playback, and background scraping can take other paths. | `modules/sources.py` (`get_sources`, `try_pack_cache`, `_process_post_results`, `_process_ignore_filters`, `play_source`), `modules/pack_continuity.py` | Enforce autoplay exclusions at the playback boundary too. Inspect the prescanned/next-episode callers before selecting the final hook. Keep intentional manual actions available. |
| TorBox cloud calculates display size from file bytes divided by 2³⁰ and rounds it. Its pack file list carries file-level size. External scrapers may divide a pack by a season/show episode count, with exceptions for certain providers. | `scrapers/tb_cloud.py`, `scrapers/external.py`, `apis/torbox_api.py` | Preserve exact values before rounding when available. Carry the estimator's provenance. Verify the Prowlarr adapter's units on actual candidates before assigning a size weight. |
| The resolver already iterates candidates, tracks failed debrid providers, and distinguishes cancellation in several branches. The player checks for a playable video, monitors playback, and stores resume progress. A pack can have multiple resolver routes to one file. | `modules/sources.py` (`play_file`, `resolve_sources`, `playback_failed_action`), `modules/player.py` (`check_playback_start`, `monitor`), `modules/pack_continuity.py` | Keep the existing loop. Remember a rejected file across clicks while preserving valid alternate routes for transport failures. Associate callbacks with the attempt that created them. |
| Display detection can distinguish HDR and Dolby Vision on some platforms and can return unknown. | `modules/display_capability.py` (`detect`, `detect_capabilities_choice`) | Reuse the device result and explicit user settings. Verify the actual Pi/display combination. |
